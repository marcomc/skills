# Private MoneyWiz profile template

Keep one profile per user outside the distributable skill/public repository. Existing
profiles can retain their format; add current policies and a dated session journal.

## Identity and current policies

Record profile owner, update date and private source locations. No credentials, OTPs,
full card numbers or authentication URLs. Separate instructions, observations and
hypotheses; explicitly link the rule that supersedes an earlier interpretation.

| Policy | Current instruction | Evidence/date |
| --- | --- | --- |
| Scope/order | Selected active accounts | Pending initial mapping |
| Sources | Preferred CLI, browser profiles, app-only products | Verify per provider |
| Cutoff/timezone | Posted/pending import policy | Verify each run |
| Authentication | Autofill/persistence preferences | User-confirmed scope |
| Mutation authority | Allowed operations and unresolved decisions | Current authorization |
| Reminders | Configured task/reminder list and occurrence rules, if used | Resolve current IDs |
| Recovery | Backup location and method | Verify before writes |

## Account map

| Identity | Current store/ID/GID | Owner/currency/product | Order/status | Source route | Accounting method |
| --- | --- | --- | --- | --- | --- |
| Resolve at first use | Refresh after migration | Distinguish similar names | Active/archive | Provider evidence | Cash, debt, aggregate or units |

Record balance scope, quote unit, net/gross income, allowed adjustments and exceptions.
A one-time amount must never become a future target.

## Merchant and relationship rules

Retain canonical payee identities, purchase-specific categories/exceptions, confirmed
account relationships and pending fuzzy decisions with dated evidence. Historical
routing does not prove every future transfer.

## Resumable session journal

Retain source observations/cutoff, transaction graph, planned actions/dependencies,
preconditions/deltas, applied IDs, readback, unknown outcomes, pending checks and
reminder occurrence. Keep enough preimage for recovery without unnecessary raw data.
Separate completed cycles from current work.

| Account | Source coverage | Ledger verification | Verified IDs / remaining | Reminder outcome |
| --- | --- | --- | --- | --- |
| Pending | Not checked | Not checked | Unknown | Leave unchanged |

Update after each verified batch, before interruptions and before finishing. Read
prior results before retries. Keep intentional skips, historical backlogs and unresolved
quote differences separate from source-verified completion.
